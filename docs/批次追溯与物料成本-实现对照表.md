## 三、分模块说明（代码依据）

### 1. 入库 `InStockService`

- 明细含 `material_batch`、`money` 等；入库后调用 `AddmaterialNum` 增加 **`wms_material`** 对应批次余额。
- **追溯/成本**：批次与单价在入库环节可落地，是后续闭环的源头。

### 2. 物料库存 `InStockService::materiallist`

- 非成品仓：按 `wms_material` 分页列表；金额行与 **`wms_in` 同批次 join** 取单价/总价（已避免「同物料多批拼一串」覆盖显示）。

### 3. 出库 `OutStockService`

- **新增出库 `add`**：逐行写入 `wms_out`，**不在此处扣库存**。
- **确认出库 `editStatus`**：应 **按 `material_id + material_batch + out_num` 扣 `wms_material`**，并回写该行 `material_batch`；若为领料类（`remark == '领料单'`），用 **同批次** 的入库单价 × 数量写入工资/扣款逻辑（`ProductReportService::addWage`）。
- **已知历史问题（已修复）**：曾调用 `AddmaterialNum($material_id, $out_num)` **未传第三参批次**，导致走「按物料 id 扣第一行库存」路径，与库管选的批次**不一致**，追溯与成本都会错。**修复**：确认出库时传入 `material_batch`。

### 4. 库存扣减 `AddmaterialNum`

- **有批次**：按 `material_id + material_batch` 扣减。
- **无批次**：仅按 `material_id` 找一条扣减——**不符合批次管理目标**，应逐步禁止非批次出库或仅限历史兼容。

### 5. PC 前端 `NewOutbound.vue`

- 从库存勾选行带出 `material_batch`、`material_num`；配件仓有「出库数量 ≤ 库存」校验。
- **缺口**：提交 `add` 的明细若仍不含 `material_batch`，单据层面批次以库管 **editStatus** 为准，存在「申请与实发批次」两段式，追溯需依赖两次数据一致。

### 6. 生产 `ProductionService::createMaterialReceiving`

- 下推生成 **领料申请**（Receiving），含 `material_id`、数量、关联计划等；**申请阶段通常无实发批次**（合理），批次应在出库确认时绑定。

### 7. 统计侧（如 `ProductionService` 配件成本 SQL）

- 已出现 `ya_wms_out` 与 `ya_wms_in` 按 **`material_id` + `material_batch`** 关联算 `material_num * money` 的思路——**前提是出库明细上 `material_batch`、`status` 正确**。

### 8. 小程序 `receiveMaterial` 等

- 个人领料申请与列表；**批次细节以 PC 出库、后端 `editStatus` 为准**，需在流程与培训上与现场对齐。

## 四、建议实施顺序（与业务无关的「技术债」优先）

1. **高**：出库确认扣库存 **必须带批次**（已修复）；服务端校验 **数量 ≤ 该批 `wms_material` 库存**（已加）；新增出库若带批次同步校验（已加）。
2. **高**：新增出库提交 **写入 `material_batch`**（已与所选库存行一并提交）。
3. **中**：禁止或限制 **无批次** `AddmaterialNum`（新材料入库强制批次）。
4. **中**：**追溯只读页**（初版：`#/report/batch-material-trace` + `traceMaterialFlow`；报工链路可二期）。
5. **低**：一单多批次拆量（多行明细或向导）。

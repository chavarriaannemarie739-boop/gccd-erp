# 圆钢主数据规范

> [AI-2026-08] 本规范统一圆钢档案、业务快照、检索与历史迁移口径。

## 四字段定义

- `material_name`：名称，仅表示业务类别，例如“圆钢”“无缝管坯”；不得填写厂商、材质或型号。
- `manufacturer`：厂商，填写生产厂家简称。
- `material_spec`：材质，填写材料牌号。
- `material_model`：型号，填写尺寸、直径等型号信息。

四个字段必须分别录入、分别展示、分别检索。禁止用斜杠、竖线、顿号、逗号、分号、加号等分隔符把多个含义或多个物料组合录入同一字段。

## 档案与业务规则

1. 圆钢档案新增、编辑按 `material_name + manufacturer + material_spec + material_model` 四字段查重；四字段去除首尾空白后完全相同即视为重复。
2. 新业务必须保存有效的圆钢 `material_id`，并保留名称、厂商、材质、型号快照用于历史展示。
3. 读取历史业务时优先按有效 `material_id` 获取当前圆钢档案；`material_id` 缺失、已删除或不再指向圆钢时，才回退到业务快照。
4. 快照回退只用于兼容历史数据，不得自动猜测或覆盖主数据；无法唯一匹配的记录进入人工审计。
5. 档案页左树仅为导航筛选（名称→厂商→材质→型号），不单独建分类表；空字段树节点展示「未填写」，筛选哨兵值为 `__EMPTY__`。
6. 四字段数据修正脚本：`php gccd_server/scripts/fix-round-steel-four-fields.php`（预览）/ `--apply`（执行）。

## 迁移操作顺序

迁移脚本：`gccd_server/scripts/migrate-round-steel-archive.php`。

部署必须严格按以下顺序执行：

1. 先执行 `gccd_server/database/material_inventory_manufacturer_snapshot.sql`，增加历史盘点厂商快照字段。该 SQL 文件保持跟踪、待部署状态，不由应用启动流程自动执行。
2. 再部署后端代码，确保新字段读写、四字段校验及历史回退逻辑同时生效。
3. 后端就绪后执行数据 `audit`；人工确认映射及门禁结果后，才可按审批执行 `apply`。
4. 最后部署管理后台构建产物和微信小程序，避免前端先发送后端尚未支持的四字段请求。

数据迁移内部操作顺序：

1. **审计**：先无参数运行。默认模式必须为 `audit`，只读取并输出空字段、组合名称、四字段冲突及无效库存关联，不更新数据库。
2. **预演映射**：人工确认后准备显式映射 JSON，使用 `--mapping=<文件>` 再次审计；解决全部未决项与四字段冲突。
3. **应用**：维护窗口内备份数据库，再显式执行 `--apply --mapping=<文件>`。应用前门禁不通过时必须停止；脚本生成带校验和的回滚备份。
4. **复核**：重新运行默认审计及契约测试，核对受影响 `material_id`、四字段唯一性和历史关联。
5. **回滚**：仅在确认需要撤销时，使用应用阶段生成的备份执行 `--rollback=<备份文件>`；回滚前必须校验当前值与备份 `after` 一致。禁止把回滚与应用同时执行。

任何环境不得跳过审计直接执行 `--apply`，不得对无法唯一判断的历史记录做自动迁移。

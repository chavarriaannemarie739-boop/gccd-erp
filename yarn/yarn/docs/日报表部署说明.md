## ⚠️ 注意事项

### 1. 向后兼容性

**领料表 `shift_type` 字段：**
- 历史数据该字段为 `NULL`
- 查询逻辑已兼容 `NULL` 值
- 不影响现有功能

**系数查询逻辑：**
- 如果系数表中没有数据，会使用默认值
- 退火丝：40元/吨
- 盘条：40元/吨
- 轧辊：100元/吨
- 天然气：3.98元/立方米

---

### 2. 数据安全性

**系数变更影响：**
- 修改系数后，只影响新报表
- 历史报表使用当时的系数（通过 `effective_date` 实现）
- 不会破坏历史数据

**软删除机制：**
- 系数删除采用软删除（`is_delete = 1`）
- 数据不会真正删除，可恢复

---

### 3. 性能优化建议

**索引已添加：**
```sql
KEY `idx_type` (`type`)
KEY `idx_effective_date` (`effective_date`)
KEY `idx_type_date` (`type`, `effective_date`)
```

**如果数据量大，建议添加：**
```sql
-- 领料表索引
ALTER TABLE ya_receiving 
ADD INDEX idx_create_time_shift (create_time, shift_type);

-- 能耗表索引
ALTER TABLE ya_product_power 
ADD INDEX idx_device_class_time (device_code, class, create_time);

-- 工资表索引
ALTER TABLE ya_user_wage_details 
ADD INDEX idx_device_date (device_code, date);
```

**检查：**
1. 数据库表是否创建成功
2. 接口是否正常返回数据
3. 浏览器控制台是否有错误

**检查：**
1. 报工记录表是否有数据
2. 领料表是否有数据
3. 能耗表是否有数据
4. 工资表是否有数据

### Q3: 系数修改后不生效？

**检查：**
1. `effective_date` 是否小于等于报表日期
2. OPcache缓存是否清除

**解决：**
```bash

访问 http://你的域名/clear_opcache.php
```
